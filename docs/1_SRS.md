# Техническое задания 

Данный документ содержит функциональные и нефункциональные требования к системе защиты веб-приложений (HTTP-фильтр/WAF), работающей по принципу Reverse Proxy. 

## Термины и определения 

WAF (Web Application Firewall) - межсетевой экран для защиты веб-приложений, анализирующий HTTP-трафик.
Reverse Proxy - сервер, который ретранслирует запросы клиентов из внешней сети на один или несколько серверов во внутренней сети.
Сигнатурный анализ - метод поиска атак по известным шаблонам (регулярным выражениям).
Эвристический анализ - выявление аномалий на основе структуры и логики данных.

## 1 Функциональные требования
### Требования к управлению пользователями 
#### Функциональное требование 1: Личный кабинет пользователя
Описание: Интерфейс для настройки защиты веб-приложений и управления ей.
Функции: Настройка проксирования (с помощью указания домена и IP-адреса), просмотр статистики трафика, просмотр детальных логов.

#### Функциональное требование 2: Панель администратора (Супер-пользователя)
Описание: Глобальное упралвение сервисом.
Функции: Упралвение учетными записями пользователей, вводе ограничений не объем трафика, редактирование реестра правил (сигнатур), мониторинг состояния системы, просмотр детальных логов. 

### Требования к аутентификации и авторизации
Графический интерфейс: Наличие форм входа и регистрации.
Механизмы: 
    1. Аутентификация по логину/паролю и подтверждение через OTP (одноразровый код).
    2. Авторизация по протоколу OAuth через стороннего провайдера GitHub.

### Требования к функциям загрузки и обработки файлов
Объемы данных: Поддержка обработки файлов от 1 Гб.

### Требования к анализу и фильтрации трафика
Сигнатурный анализ: Выявление SQL-инъекций, XSS-атак и Path Traversal с использованием регулярных выражений.
Эвристический анализ: Обнаружение аномальной длины запросов, высокой плотности спецсимволов и частоты запросов с одного IP-адреса.

## 2 Требования к интерфейсам
### Требования к графическому интерфейсу управления администратора системы
    1. Модулья управления пользователями: список всех зарегистрированных клиентов с возможностью блокировки учетных записей, просмотра их активных сессий и деактивации подозрительных сеансов.
    2. Реестр правил и сигнатур: редактор для добавления и удаления регулярных выражений, используемых для поиска SQL-инъекций, XSS-атак и Path Traversal.
    3. Панелья мониторинга инфраструктуры: визуализация вреальном времения нагрузки на систему, потребления ресурсов CPU/RAM сервером фильтрации и состояния базы данных PostgreSQL.
    4. Смена пароля пользователей: возможность изменять пароль для любого из пользователей. 
    5. Управление токенами доступа: функицонал выпуска и отзыва токенов доступа для внешних приложений, работающих с системой.

### Требования внешним интерфейсам системы HTTP API
    1. Принцип проектирования: API должен быть построен на принципах REST.

### Требования к графическому интерфейсу пользователя системы
    1. Настройка проксирования: форма ввода домена и IP-адрема сервера.
    2. Статистика: графики трафика с разделением на "легитимный" и "вредоносный", а также диаграммы распределения атак по категориям.
    3. Просмотр логов: записи о каждом заблокированном запросе, включая IP-адрес атакующего, полную строку запроса и причину блокировки. 
    4. Управление аватаром: возможность загружать и изменять собственный аватар.

## 3 Нефункциональные требования
### Требования к обработке больших данных
    1. Система должна обеспечивать стабильное проксирование трафика без значительных задержек при анализе.

### Требования к безопасности
    1. Использование веб-сервера Nginx и защита протоколом TLS.
    2. Настройка SOP, CORS и политик безопасности контента (CSP) для предотвращения атак на панель управления. 

### Требования к инфраструктуре
    1. Использование СУБД PostgreSQL.
    2. Автоматическая сборка дистрибутивов, использование семантического версионирования, безопасное хранение секретов в CI/CD Variables.
