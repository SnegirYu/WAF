# Руководство пользователя

# 1. Описание операций пользователя
## 1.1. Регистрация нового пользователя с подтверждением почты
1. **Наименование:** Регистрация учетной записи пользователя в системе.
2. **Условия выполнения:**
   - Пользователь имеет доступ к сети Интернет и действующий адрес электронной почты.
3. **Подготовительные действия:** Открыть веб-браузер и перейти по URL-адресу главной страницы панели WAF.
4. **Основные действия:**
   - Перейти в браузере  на URL `/register/`.
   - Заполнить форму регистрации, указав: имя пользователя (username), email, пароль и подтверждение пароля.
   - Нажать кнопку «Зарегистрироваться».
   - Дождаться системного уведомления об отправке письма и перейти в свой почтовый ящик.
   - Открыть письмо от WAF Panel и кликнуть по уникальной ссылке подтверждения (переход по URL `/verify/<token>/`).
5. **Заключительные действия:** После успешного подтверждения почты система перенаправит пользователя на страницу входа `/login/` с уведомлением об успешной активации аккаунта.

## 1.2. Аутентификация по логину и паролю
1. **Наименование:** Вход пользователя в систему по локальным учетным данным.
2. **Условия выполнения:**
   - Учетная запись пользователя зарегистрирована и активирована.
3. **Подготовительные действия:** Перейти на страницу входа `/login/`.
4. **Основные действия:**
   - В форме ввода указать username и пароль.
   - Нажать кнопку «Войти».
   - *Примечание:* Если для аккаунта включена двухфакторная аутентификация (2FA), система перенаправит на страницу `/verify-2fa/`, где необходимо ввести актуальный 6-значный одноразовый код (OTP) из приложения-аутентификатора и нажать «Подтвердить».
5. **Заключительные действия:** При успешной проверке данных учетной записи (и OTP-кода, если он активен) пользователь перенаправляется в личный кабинет (URL `/dashboard/`), а в верхнем меню отображается его имя.

## 1.3. Аутентификация через сторонний сервис GitHub (OAuth)
1. **Наименование:** Вход в систему с использованием учетной записи GitHub.
2. **Условия выполнения:**
   - Наличие активного аккаунта на платформе GitHub.
3. **Подготовительные действия:** Перейти на страницу входа `/login/`.
4. **Основные действия:**
   - На странице входа нажать на кнопку «Войти через GitHub».
   - Система перенаправит пользователя на официальный сайт GitHub для авторизации приложения WAF.
   - При необходимости ввести учетные данные от GitHub и подтвердить предоставление прав (чтение email и username).
5. **Заключительные действия:** Система автоматически создаст (при первом входе) или найдет существующий профиль пользователя и перенаправит его на страницу `/dashboard/`.

## 1.4. Настройка двухфакторной аутентификации (2FA)
1. **Наименование:** Подключение и активация одноразовых паролей (TOTP) для защиты аккаунта.
2. **Условия выполнения:**
   - Пользователь успешно авторизован в личном кабинете.
   - На мобильном устройстве пользователя установлено приложение для генерации кодов (например, Google Authenticator, Яндекс Ключ).
3. **Подготовительные действия:** Нажать на кнопку "Настроить 2Fa" в личном кабинете (переход по URL `/2fa/setup/`).
4. **Основные действия:**
   - На открывшейся странице отсканировать отображаемый QR-код с помощью мобильного приложения-аутентификатора.
   - В поле подтверждения на сайте ввести сгенерированный приложением текущий 6-значный цифровой код.
   - Нажать кнопку «Активировать 2FA» для верификации и сохранения настроек (переход на `/2fa/verify/`).
5. **Заключительные действия:** Система выдает сообщение об успешной активации двухфакторной аутентификации. При последующих авторизациях ввод OTP-кода станет обязательным.

## 1.5. Изменение аватара профиля
1. **Наименование:** Загрузка и обновление аватара пользователя.
2. **Условия выполнения:**
   - Пользователь успешно авторизован в системе.
   - Подготовлен графический файл (форматы PNG/JPG).
3. **Подготовительные действия:** Перейти в личный кабинет.
4. **Основные действия:**
   - В блоке управления аватаром нажать кнопку «Выбрать файл».
   - В диалоговом окне выбрать подготовленное изображение.
   - Нажать кнопку «Сохранить изменения».
   - Нажать кнопку «Обновить аватар».
5. **Заключительные действия:** Страница обновляется, новое изображение пользователя начинает отображаться.

## 1.6. Смена пароля пользователя
1. **Наименование:** Безопасное изменение текущего пароля из личного кабинета.
2. **Условия выполнения:**
   - Пользователь авторизован в системе.
3. **Подготовительные действия:** Перейти в личный кабинет.
4. **Основные действия:**
   - В форме смены пароля заполнить поля: «Текущий пароль» и «Новый пароль».
   - Нажать кнопку «Обновить пароль».
5. **Заключительные действия:** Система проверяет корректность старого пароля, сохраняет изменения в БД и выводит уведомление об успешной смене пароля.

## 1.7. Добавление веб-сайта под защиту WAF
1. **Наименование:** Регистрация нового домена в системе для фильтрации трафика.
2. **Условия выполнения:**
   - Пользователь авторизован в системе.
   - Общее количество уже добавленных пользователем сайтов строго меньше 5.
3. **Подготовительные действия:** Подготовить данные целевого ресурса (доменное имя и реальный IP-адрес сервера, где развернут сайт). Находясь в `/dashboard/`.
4. **Основные действия:**
   - В появившейся форме ввести защищаемый домен (например, `mysite.ru`).
   - Указать целевой IP-адрес (Target IP) бэкенд-сервера, на который WAF-Engine должен перенаправлять легитимный трафик.
   - Нажать «Создать / Добавить сайт».
5. **Заключительные действия:** Если лимит в 5 сайтов не исчерпан, новый сайт появляется в таблице личного кабинета со статусом «Защита активна».

## 1.8. Выгрузка журналов безопасности (логов)
1. **Наименование:** Скачивание файла логов в формате CSV.
2. **Условия выполнения:**
   - Пользователь авторизован в системе.
   - Добавлен сайт для защиты.
3. **Подготовительные действия:** Перейти в личный кабинет.
4. **Основные действия:**
   - Нажать на кнопку "Сгенерировать логи".
   - Нажать на кнопку "Скачать файл".
5. **Заключительные действия:** Браузер инициализирует скачивание файла на локальное устройство пользователя для последующего анализа.

## 1.9. Написание официального обращения к администратору
1. **Наименование:** Отправка текстового сообщения в службу технической поддержки WAF.
2. **Условия выполнения:**
   - Пользователь авторизован в системе.
3. **Подготовительные действия:** Перейти в личный кабинет.
4. **Основные действия:**
   - Заполнить форму обратной связи: указать тему обращения и подробно описать возникшую проблему или вопрос в текстовом поле.
   - Нажать кнопку «Отправить сообщение».
5. **Заключительные действия:** Сообщение отправляется администратору. Пользователь получает уведомление о том, что обращение успешно доставлено.

## 1.10. Выход из системы
1. **Наименование:** Завершение сессии.
2. **Условия выполнения:**
   - Пользователь авторизован в системе.
3. **Подготовительные действия:**Перейти в личный кабинет.
4. **Основные действия:**
   - Нажать на кнопку «Выйти» (вызов URL `/logout/`).
   - Подтвердить деавторизацию.
5. **Заключительные действия:** Перенаправление пользователя на страницу авторизации `/login/`.

# 2. Описание операций администратора
## 2.1. Аутентификация администратора
1. **Наименование:** Вход администратора в панель управления.
2. **Условия выполнения:**
   - Учетная запись существует в Системе и е=имеет роль администратора.
3. **Подготовительные действия:** Открыть браузер и перейти на страницу `/login/`.
4. **Основные действия:**
   - Ввести Email/Username и пароль администратора.
   - Нажать кнопку «Войти».
   - При наличии активной двухфакторной аутентификации ввести 6-значный код TOTP на странице `/verify-2fa/`.
5. **Заключительные действия:** Перенаправление на административную панель (`/panel/`).

## 2.2. Мониторинг состояния системы
1. **Наименование:** Просмотр метрик производительности сервера WAF.
2. **Условия выполнения:**
   - Администратор успешно авторизован.
3. **Подготовительные действия:** Перейти в раздел мониторинга по URL `/panel/monitoring/`.
4. **Основные действия:**
   - Проанализировать текущее потребление аппаратных ресурсов: нагрузка на процессор (CPU), использование оперативной памяти (RAM), свободное дисковое пространство, количество запросов в минуту.
5. **Заключительные действия:** Использование полученных данных для оперативного принятия решений о масштабировании или очистке диска.

## 2.3. Просмотр и скачивание глобального журнала логов
1. **Наименование:** Аудит всех зафиксированных инцидентов безопасности в системе.
2. **Условия выполнения:**
   - Администратор успешно авторизован.
3. **Подготовительные действия:** Перейти в раздел журналов по URL `/panel/logs/`.
4. **Основные действия:**
   - Нажать на кнопку "Сгенерировать логи".
   - Нажать на кнопку "Скачать файл".
5. **Заключительные действия:** Браузер скачивает файл отчета, содержащий данные о сетевых угрозах для всех клиентских сайтов.

## 2.4. Изменение роли пользователя
1. **Наименование:** Назначение или отзыв административных привилегий у учетной записи.
2. **Условия выполнения:**
   - Администратор успешно авторизован.
3. **Подготовительные действия:** Перейти в раздел управления пользователями `/panel/users/` и открыть карточку конкретного пользователя `/panel/users/<id>/`.
4. **Основные действия:**
   - В блоке прав изменить статус роли (например, переключить чекбокс «Администратор»).
   - Нажать кнопку «Сохранить».
5. **Заключительные действия:** Роль пользователя мгновенно изменяется в БД, при следующем запросе его уровень доступа пересчитывается системой.

## 2.5. Смена тарифного плана пользователя
1. **Наименование:** Привязка пользователя к определенному тарифному пакету.
2. **Условия выполнения:**
   - Администратор успешно авторизован..
3. **Подготовительные действия:** Перейти в раздел управления пользователями `/panel/users/` и открыть карточку конкретного пользователя `/panel/users/<id>/`.
4. **Основные действия:**
   - В выпадающем списке «Тарифный план» выбрать необходимый пакет (например, «Базовый», «Безлимитный», «Бизнес»).
   - Нажать «Обновить тариф».
5. **Заключительные действия:** Изменяются системные лимиты пользователя на максимальное количество добавляемых сайтов и объем доступного трафика.

## 2.6. Принудительная смена пароля пользователя
1. **Наименование:** Административный сброс пароля учетной записи в случае компрометации.
2. **Условия выполнения:**
   - Запрос от пользователя.
3. **Подготовительные действия:** Перейти в раздел управления пользователями `/panel/users/` и открыть карточку конкретного пользователя `/panel/users/<id>/`.
4. **Основные действия:**
   - Ввести новый сложный пароль в поле ввода.
   - Нажать кнопку «Сменить пароль».
5. **Заключительные действия:** Польхователю назначается новый пароль.

## 2.7. Блокировка и разблокировка учетной записи пользователя
1. **Наименование:** Принудительное ограничение доступа пользователя к его личному кабинету.
2. **Условия выполнения:**
   - Нарушение правил использования сервиса или подозрительная активность аккаунта.
3. **Подготовительные действия:** Перейти в раздел управления пользователями `/panel/users/` и открыть карточку конкретного пользователя `/panel/users/<id>/`.
4. **Основные действия:**
   - В разделе "Блокировка аккаунта" нажать на кнопку "Заблокировать"/"Разблокировать".
5. **Заключительные действия:** Статус пользователя меняется.

## 2.8. Временное отключение защиты для сайта пользователя
1. **Наименование:** Перевод WAF-Engine в режим пропуска (Bypass) для конкретного домена.
2. **Условия выполнения:**
   - Запрос от пользователя или необходимость.
3. **Подготовительные действия:** Перейти в раздел управления пользователями `/panel/users/` и открыть карточку конкретного пользователя `/panel/users/<id>/`.
4. **Основные действия:**
   - Найти нужный сайт и пнажать на кнопку "Отключить защиту".
5. **Заключительные действия:** WAF продолжает проксировать трафик на сайт пользователя, но перестает блокировать вредоносные сигнатуры.

## 2.9. Принудительное завершение сессий пользователей
1. **Наименование:** Завершение активных браузерных сессий пользователей.
2. **Условия выполнения:**
   - Экстренная необходимость.
3. **Подготовительные действия:** Перейти в раздел активных сессий по URL `/panel/sessions/`.
4. **Основные действия:**
   - Найти сессию по Username пользователя или идентификатору сессионного ключа.
   - Нажать кнопку «Завершить».
5. **Заключительные действия:** Запись сессии удаляется из таблицы `django_session`. 

## 2.10. Добавление новых сигнатур и правил фильтрации WAF
1. **Наименование:** Расширение базы знаний WAF для защиты от новых уязвимостей.
2. **Условия выполнения:**
   - Администратор успешно авторизован.
3. **Подготовительные действия:** Перейти в раздел управления правилами `/panel/rules/`.
4. **Основные действия:**
   - Заполнить форму: Название, Сигнатура / Паттер, Описание, Критичность, Действие и Статус.
   - Нажать «Добавить».
5. **Заключительные действия:** Новое правило записывается в базу данных и автоматически подтягивается модулем фильтрации движка WAF.

## 2.11. Включение и отключение правил WAF
1. **Наименование:** Оперативное управление активностью отдельных сигнатур безопасности.
2. **Условия выполнения:**
   - Необходимость временно отключить правило.
3. **Подготовительные действия:** Открыть список правил по URL `/panel/rules/`.
4. **Основные действия:**
   - Найти сигнатуру по её названию.
   - Нажать на кнопку "Откл." / "Вкл.".
5. **Заключительные действия:** Движок WAF-Engine мгновенно прекращает или возобновляет учет данной сигнатуры при анализе входящего HTTP-трафика.

## 2.12. Смена собственного пароля администратора
1. **Наименование:** Регламентное обновление пароля от учетной записи администратора.
2. **Условия выполнения:**
   - Администратор авторизован в системе.
3. **Подготовительные действия:** Перейти в личные настройки профиля по URL `/panel/password/`.
4. **Основные действия:**
   - Ввести текущий пароль администратора.
   - Ввести новый пароль и его подтверждение.
   - Нажать кнопку "Сохранить пароль".
5. **Заключительные действия:** Система обновляет секретные данные учетной записи администратора в базе.

## 2.13. Смена аватара профиля администратора
1. **Наименование:** Обновление изображения администратора.
2. **Условия выполнения:**
   - Подготовлен файл изображения.
3. **Подготовительные действия:** Перейти в настройки профиля `/panel/avatar/`.
4. **Основные действия:**
   - Нажать кнопку "Выбор файла", выбрать изображение с локального диска.
   - Нажать "Загрузить".
5. **Заключительные действия:** Новый аватар отображается на панеле администрирования.

## 2.14. Просмотр и обработка обращений пользователей
1. **Наименование:** Чтение входящих сообщений из формы обратной связи клиентов панели.
2. **Условия выполнения:**
   - Наличие отправленных пользователями сообщений.
3. **Подготовительные действия:** Перейти на главную страницу панели администратора.
4. **Основные действия:**
   - Открыть список обращений.
   - Ознакомиться со смыслом проблемы, нажать на кнопку «Отметить как прочитано».
5. **Заключительные действия:** Статус сообщения в БД меняется на "Прочитано".

## 2.15. Завершение сеанса работы администратора (Выход)
1. **Наименование:** Безопасный выход из панели администратора.
2. **Условия выполнения:**
   - Администратор завершил текущую рабочую сессию.
3. **Подготовительные действия:** Нажать кнопку «Выйти» в боковом меню.
4. **Основные действия:**
   - Подтвердить деавторизацию.
5. **Заключительные действия:** Браузер принудительно перенаправляет пользователя на общую страницу входа `/login/`.
